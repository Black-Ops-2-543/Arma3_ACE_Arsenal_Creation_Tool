## Root causes and corrections

1. **Indexed resolver fall-through.** The catalogue index contained the expected row, but `exitWith` was nested inside a normal `then` scope. It returned from that scope and the function continued to its unavailable result. The outer row-found condition now exits the function and returns the row's actual bucket. A permanent engine assertion now checks direct resolution of `arifle_MX_F`.
2. **Whole-input generic lexer allocation.** Generic recovery converted the complete source to a numeric character array. The first correction bounded that allocation to 65,536-character windows and preserved quote/comment state across boundaries. The final correction uses native offset-based structural-token scans and immediately consumes each completed literal, so neither a whole-input numeric array nor a global token corpus is retained. The boundary fixture still places a comment delimiter across the former window boundary.
3. **Invalid malformed-envelope test expression.** The test no longer invokes `regexReplace` for a literal bracket; it uses deterministic substring replacement.

The corrected code is commit `297d24b` (`fix(import): restore indexed recovery and bound lexer memory`). Static validation and clean PBO build pass. Runtime confirmation is intentionally pending.
